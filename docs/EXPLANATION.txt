Project Explanation - Full Stack Exam Management System
=======================================================

Project Goal
------------
This project is a full stack web application for managing online exams and student submissions.
The system supports two main users: lecturers/teachers and students.

Main Users
----------
1. Lecturer / Teacher
The teacher can create exams, add questions, choose question types, publish exams, close exams, review student submissions, update grades, write feedback and publish results.

2. Student
The student can register, login, view published exams, enter an exam, answer questions, submit the exam and view grades and feedback.

Technology Stack
----------------
Frontend:
React + Vite.

Backend:
Node.js + Express REST API.

Database:
PostgreSQL.

Authentication:
JWT tokens and bcrypt password hashing.

DevOps:
Docker, Docker Compose and GitHub Actions CI/CD.

Main Features
-------------
1. Authentication and Authorization
Users can register and login. The backend returns a JWT token. Protected routes require the token. Role-based authorization separates teacher and student permissions.

2. Exam Management
Teachers can create exams with title, course, description, time limit and questions. The system supports multiple-choice, true/false and open-text questions.

3. Exam Publishing
Teachers can keep exams as draft, publish them to students, or close them after the exam ends.

4. Student Submission
Students can view only published exams. The exam page includes a timer. When the student submits, answers are saved in PostgreSQL.

5. Grading
Multiple-choice and true/false questions are graded automatically. Open-text questions can be reviewed manually by the teacher. Teachers can edit grades and add feedback.

6. Results
Students can view published results, feedback and their personal average.

7. Analytics
Teachers can view class average, highest grade, lowest grade, number of active students and a visual grade comparison graph.

8. Database Design
The database includes users, exams and submissions. The questions and answers are stored as JSONB fields, which makes the system flexible for multiple question types.

9. Frontend/Backend Communication
The React frontend communicates with the Express backend using fetch requests to REST endpoints under /api.

10. Deployment
The project includes Docker Compose for running frontend, backend and PostgreSQL together. It also includes a GitHub Actions workflow for build, tests and security audit.

Why This Meets the Requirements
-------------------------------
- Frontend application: React.
- Backend API: Express.
- Database integration: PostgreSQL.
- Authentication and authorization: JWT + role middleware.
- Persistent data storage: PostgreSQL tables.
- Cloud/server readiness: environment variables and deployment guide.
- Documentation: architecture, database diagram, API documentation and run guide.
- Added features: analytics, timer, feedback, Docker and CI/CD.
